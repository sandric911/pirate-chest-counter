# Решения

Журнал решений, принятых без участия автора (раздел 6 ТЗ). Новые записи — внизу.

## 2026-11-08

1. **Парсер без форка.** v43.00 читается NuGet-пакетом `FortniteReplayReader` 3.1.0 как есть. Недостающее
   (`SearchingPawn`, причина закрытия канала, время кадра) добавлено наследником `ChestReplayReader` через
   виртуальные методы `ReceiveProperties`, `ReceivedSequencedBunch`, `ReadDemoFrameIntoPlaybackPackets`.
   Свойства контейнеров читаем сами, а не через модели upstream: модели `Chest`/`BaseContainer` не знают
   `SearchingPawn`, а дублировать группу с тем же путём нельзя (upstream берёт первую попавшуюся).
   Форк + submodule + PR понадобятся, только если upstream сломается на будущем билде.
2. **Сборка с «ReplayReader» в имени.** `NetFieldParser` upstream сканирует только сборки с этой подстрокой,
   поэтому адаптер называется `PirateChest.ReplayReader` (на будущее, если понадобятся свои группы).
3. **«Сломан» = `bDestroyed`, а не `closeReason == Destroyed`.** В клиентском реплее канал закрывается с
   `Destroyed` и тогда, когда клиент просто выгрузил актор (стриминг мира). Проверено: 717 закопанных и
   330 реликвийных сундуков «уничтожались» через 7 с после появления без единого изменения. Логика xNocken
   (closeReason 0) верна для серверных реплеев, но не для клиентских. `closeReason` используем только чтобы
   связать «обыск без bAlreadySearched» с последующим уничтожением (окно 7 с).
4. **Кто сломал — из реплея.** Игра при поломке неоткрытого сундука делает обыск от имени сломавшего
   (`SearchAnimationCount`+1, `SearchingPawn`). Это и есть «инициатор урона» из правила 6. `EffectContext`
   на сундуках встречается редко (≈1 на матч) и не нужен. Эвристика (R = 15 м, ±2 с) — только для
   `bDestroyed` без обыска.
5. **Координаты статических сундуков — «атлас».** Своих координат у них в реплее нет. Позиция открывшего
   в момент открытия (±2 м) копится по статическому имени актора (`…_UAID_…`, оно стабильно между матчами).
   Атлас хранится в базе и пополняется каждым матчем; он нужен карте и эвристике.
6. **Ключ сундука (правило 2):** статическое имя актора; для динамических — класс + координаты появления
   с допуском 3 м (у них новый NetGUID при каждом возвращении в зону видимости).
7. **Сброс сундуков игрой.** В v43 часть открытых сундуков в определённые моменты матча снова становится
   закрытой. Повторный обыск того же сундука в том же матче не засчитывается (правило 2) и считается в
   диагностике `ReopenedAfterReset`. За 96 матчей таких повторов у меня 0.
8. **Treasure Hunt** — это не отдельный класс сундука, а маркер `BGA_DelilahTreasureHuntAnimatedChest_C`
   с полем `SourceContainer`, указывающим на обычный сундук. Такой сундук получает тип «Treasure Hunt».
9. **Тип сундука:** `AlwaysSpawn_RareChest_C` или тир ≥ 2 → «редкий»; закопанные/реликвийные → «другой».
   Классы и типы — в `chest-classes.json`.
10. **Фильтр матчей:** билд 43.x и дата с 31.10.2026 12:00 UTC по 06.12.2026 12:00 UTC (запас на часовые
    пояса), плейлисты `Playlist_Default{Solo,Duo,Trio,Squad}`, `Playlist_NoBuildBR_*` и рейтинговые
    (`Habanero`/`Showdown`). Отдельной проверки карты нет: `MapInfo` в v43 не реплицируется, а все BR/ZB
    плейлисты билда 43 идут на Crossbones Isle.
11. **POI без названий.** В реплее нет имён POI (только хэши ячеек World Partition). Места высадки
    кластеризуются; названия подписываются по скриншоту карты и редактируются в UI.
12. **Конец активной игры** для «сундуков в минуту» — последний момент, когда существовал мой персонаж
    (смерть без возрождения или конец матча); «до смерти» — до первой смерти.
13. **Время матча.** `ReplayInfo.Timestamp` — локальное время ПК, где шла запись (UE `FDateTime::Now`), хотя
    библиотека отдаёт его как есть. Переводим в UTC по часовому поясу этого ПК (проверено: файл
    `…2026.11.04-00.27.53` записан в 21:36 UTC 3 ноября, ПК в UTC+3).
14. **Регрессионные ленты** (`tests/…/Regression/*.json.gz`): только сундуки и позиции отряда, без ников,
    ID аккаунтов и ID реплея. Ожидаемые значения — снимок результата на момент коммита; любое изменение
    правил, которое их сдвигает, должно быть осознанным (`REGRESSION_UPDATE=1` перезаписывает снимок).
15. **Дочерние процессы — через ShellExecute.** Иначе запущенная копия наследует stdout-конвейер, и
    `--install | Out-Host` в PowerShell висит, пока программа работает (поймано на тесте).
16. **Двойной щелчок по скачанному exe = установка** (как `--install`, но с окном). Так ручная установка не
    требует командной строки; запуск из папки установки — обычный запуск.
17. **«Не заблокирован»** проверяется без попытки захватить файл: реплеи открываются только с
    `FileShare.ReadWrite|Delete`, поэтому «закончен» = заголовок не IsLive + файл не менялся 30 с.
    Реплей, оставшийся IsLive после падения игры, пробуется через 3 часа.
18. **Текущая сессия** — цепочка матчей с перерывами меньше 45 минут, если последний закончился меньше 45 минут назад.
19. **Обновление** применяется, только когда программа установлена в `%LOCALAPPDATA%\Programs`; новый exe
    скачивается только по ссылке на `github.com`, сверяется с `SHA256SUMS.txt` того же релиза и подменяет
    старый через вспомогательный процесс `PirateChestCounter.update.exe`, который потом удаляется.
    Проверено: v1.0.0 → v1.0.1 сама за 25 секунд после запуска.
20. **Место в матче** берётся из события `TeamStats` реплея (у `PlayerState.Place` бывают пропуски).
