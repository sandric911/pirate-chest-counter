# Что может сломаться после обновления Fortnite и как чинить

Признак поломки: на вкладке «Обновления» в «Очереди и ошибках разбора» появляются реплеи со статусом «ошибка»,
или счётчик после матча растёт заметно меньше, чем вы открыли. Реплеи с ошибкой не теряются: после выхода
исправленной версии они пересчитаются сами (пока Fortnite их не удалил — он хранит около 100 последних).

## Диагностика за 5 минут

```powershell
dotnet run --project tools/PirateChest.Spike -c Release -- "$env:LOCALAPPDATA\FortniteGame\Saved\Demos" spike-out
```

Отчёт покажет: сколько реплеев разобралось, билды, плейлисты, все классы с «Chest», какие поля сундуков
читаются с ошибкой (`BAD`), какие поля upstream стали `Incompatible`. Сравните с [SPIKE_REPORT.md](SPIKE_REPORT.md).
`SPIKE_RAW=1` дополнительно пишет в ленты все сырые поля контейнеров.

## Типичные поломки

| Что видно | Причина | Что делать |
|---|---|---|
| Все новые реплеи падают с исключением | изменился формат (сжатие, шифрование, заголовок) | обновить NuGet `FortniteReplayReader`; если upstream ещё не починили — форкнуть Shiqan/FortniteReplayDecompressor, подключить submodule, сделать точечный патч (пример — фикс #77 для 41.00), открыть PR |
| Разбор идёт, но сундуков 0 | поле переименовано или сменило тип (`bAlreadySearched`, `SearchingPawn`, `SearchAnimationCount`, `bDestroyed`) — видно как `BAD` в отчёте spike | поправить чтение в `ChestReplayReader.ReadContainer` |
| Появился новый вид сундука | новый класс в отчёте spike | добавить в `src/PirateChest.Core/chest-classes.json`; неизвестные классы с «Chest», на которых был обыск, и так считаются «другими» |
| Матчи нового сезона в «Пропущено» | новый билд/даты/плейлисты | `MatchFilter`: `AllowedBuildMajors`, `FromUtc/ToUtc`, `PlaylistPatterns` |
| Неверная высадка/время | изменились флаги парашюта у `PlayerPawn` | `ChestReplayReader.OnExportRead`, `MatchAnalyzer.FindLanding` |
| Новая карта | другой остров | новый `assets/map.png` (скриншот из игры) и привязка к нему (`assets/calibration.json`, `tools/assets/pois_from_map.py`), новые места в `pois.json`; затем `python tools/assets/build_map_tiles.py` — скачает официальную карту, сопоставит её со скриншотом и пересоберёт `assets/maptiles` (тайлы, привязка, ориентиры). Атлас сундуков переучится сам |

После исправления: поднять `ChestReplayReader.ParserVersion` (тогда все матчи пересчитаются у пользователей
автоматически), прогнать `dotnet test`, поставить тег `vX.Y.Z` (или на GitHub: Actions → release → Run workflow на `main`, в поле версии `X.Y.Z` — тег создастся сам) — CI выпустит релиз, а установленные программы
обновятся сами в течение 6 часов.

## Журнал: подсчёт сразу после матча

`%LOCALAPPDATA%\PirateChestCounter\log.txt`. У матча, посчитанного сразу после записи, в строке есть время:
`(412 ms, 530 ms after Fortnite wrote it)` — разбор и всё время от последней записи Fortnite до сохранения.

| Строка | Что значит | Что делать |
|---|---|---|
| `not counted yet, …` | у реплея готовый заголовок, но файл неполный (решение 74); программа ждёт остальное | ничего; если так у каждого матча и следом идёт `counted although …`, Fortnite стал писать реплей иначе: число верное, но появляется на 3 с позже — смотреть `ReplayLayout`/`ReplayFiles.Inspect` |
| `changed after it was counted … counting it again` | Fortnite писал в файл после готового заголовка; матч пересчитан | разово — ничего; у каждого матча — то же, что выше |
| `early read failed …` | разбор сразу после записи упал; будет повтор через 30 с тишины | если после повтора «ошибка» — см. таблицу выше |
| `ERROR … reading only the pawn fields …` | ускоренное чтение персонажей дало другой результат, чем полное (решение 77); программа сама вернулась к полному и пересчитала матчи | сравнить поля в `PawnGroups.UsedFields` с тем, что читает `ChestReplayReader.OnExportRead`; после исправления выпустить версию — проверка повторится сама |

## Карта во вкладке «Карта»

`assets/maptiles` собирает `tools/assets/build_map_tiles.py` (`pip install opencv-python-headless pillow numpy`):
официальная карта 2048×2048 — уровни 0–3, увеличенные — 4–5 над островом; вид «Как в игре» — из `assets/map.png`.
Если есть картинка острова лучше (например, своя сшитая из скриншотов в 4K), добавьте её как ещё один вид:
`--style hd=путь.png` — она сама сопоставится с официальной картой, а уровней «своего» разрешения станет больше.
Названия видов — `STYLE_NAMES` в скрипте. После пересборки меняется версия в `map.json`, и окно перестаёт брать
тайлы из кэша.
